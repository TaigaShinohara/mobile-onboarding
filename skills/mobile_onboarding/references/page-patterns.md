# ページのパターン集

モバイルオンボーディングの9つのページ型と、テンポと演出の設計。1ページに役割を2つ与えず、1ページの主張は1つに絞る。

## 9つのページ型

### フック

- 役割：最初の1ページで引き込む。共感できる困りごとや、意外な一言を置く。
- 見出し：ユーザーの場面をそのまま表す一言、または「え、それできるの」と思わせる主張。
- 視覚の主役：その場面を表すイラストや図形、または本体の画面の一部分。
- 動き：入口で1回だけ強いアニメーションを使う。ループさせない。
- 操作：画面のどこをタップしても次へ進む。

### 選択（悩み・希望）

- 役割：ユーザーの悩みや希望を1つ選ばせる。マッチ宣言と対で使う。このページの内容は質問だけである。
- 見出し：質問そのものを1行で書く（例：いちばん困っているのはどれですか）。
- 選択肢：ちょうど3つ（3択固定）。1つ目と2つ目は具体的な場面や気持ちの文で書き、3つ目は必ず「その他」「まだわからない」に当たる逃げ道にする。
- ボタン：「次へ」ボタンは置かない。選択肢を押すことが決定と前進を兼ねる。
- 返しと遷移：選んだ瞬間に「押したら、褒める」の中段階の反応（弾み、称賛、成功の触覚）を現在のページで250〜400ミリ秒返し、称賛が読める余韻（タップから合計900〜1,200ミリ秒が目安）を置いてから、結果のページ（マッチ）へ自動で進む。反応と次ページを同時に出さない。結果の文章をこのページに表示しない。順番の詳細は本編の「反応と次ページの順番（同時に出さない）」に従う。
- 枚数：マッチ宣言までに最大2ページ。詳しくは「選択とマッチの流れ」を使う。

### マッチ（結果のページ）

- 役割：選んだ悩みや希望を受けて「そんなあなたにはこのアプリがぴったり」と宣言する。質問のページとは分けた、結果だけのページである。質問と選択肢は再掲しない。
- 見出し：ユーザーが選んだ言葉を映した宣言を1行で書く。
- 補足：ぴったりの根拠として、その悩みに直接効く強みを1つだけ挙げる。機能の一覧は書かない。
- 視覚の主役：選んだ選択肢とアプリが結びつく図形。選択肢のアイコンがアプリ側へ寄る、重なるなどの「合う」動きで見せる。
- 引き継ぎ：このページの後に来る価値のページは、選んだ内容に対応するものから並べる。

### アイデンティティ

- 役割：何のためのアプリかを宣言する。1ページ1宣言。
- 見出し：コンセプトを1行で言い切る。社名やロゴの紹介で代替しない。
- 視覚の主役：アプリの姿を表す画面モックや象徴的なアイコン。
- 配置：オンボーディングの前半に置き、ステップより後へ回さない。

### 価値

- 役割：使うと何が変わるかを示す。1価値1ページ。
- 見出し：ユーザーが得られる変化を一言で書く。機能名ではなく変化を書く。
- 視覚の主役：変化の前後を比べる図、または変わった後の場面。
- 枚数：1〜3ページ。4つ以上の価値は、初回に要らないものを削る。

### ステップ

- 役割：基本的な使い方の1ステップを示す。ちょうど3ページで1セット。
- 見出し：動詞で始める。番号を大きく見せる。
- 視覚の主役：その操作を表す画面モックや手元の動きを示す図形。実際の操作画面に近い見た目にする。
- 連続性：3ページで同じ構図を保ち、変わる部分だけを動かす。ステップ間で学び直しを発生させない。
- 最終ステップのページでは、操作の結果として得られる状態を視覚で示す。

### インタラクション

- 役割：選択、回答、試し操作をさせる。1ページ1問。
- 見出し：質問そのものを1行で書く。
- 選択肢：ちょうど3つ（3択固定、3つ目は「その他」「まだわからない」系の逃げ道）、大きくタップできるサイズで並べる。自由記述は求めない。
- ボタン：質問のページには「次へ」ボタンを置かない。押したら現在のページで反応を返し、余韻を置いてから自動で進む（反応と次ページを同時に出さない）。行き先は、残りの質問がある場合は次の質問のページ、なければ結果のページとする。
- 返し：結果（タイプ表示、診断の返し、一言のフィードバック）は、このページではなく次の結果ページで単独で示す。このページで返すのは押した瞬間の短い反応だけである。
- 置き場所：価値とステップの合間に散らす。連続2ページはインタラクションにしない。ただし選択とその結果の2ページは、対として連続させてよい。

### 期待

- 役割：ワクワクの山場を示す。使い続けると広がる楽しさや、到達できる場面を見せる。
- 見出し：未来の体験を一言で書く。
- 視覚の主役：いちばん映える場面や、成果物の例、続けると育つ要素。
- 位置：接続ページの直前に置く。途中の価値ページにも小さな山場を置いてよい。

### 接続

- 役割：本体の最初の行動へ渡す。
- 見出し：「はじめよう」ではなく、本体で最初にやることを書く。
- ボタン：押した先の画面と行動がわかるラベルにする。
- 引き継ぎ：オンボーディングの回答と試し操作の結果を、本体の初期状態に反映する。

### 許可と登録のページ（必要な場合）

- 役割：権限の許可、アカウント作成、通知の設定のいずれか1つだけ。
- 見出し：なぜ必要かを1行で書く。求める操作の名ではなく、必要になる場面を書く。
- 順序：価値が伝わった後に置く。価値の前に置かない。
- システムのダイアログ：アプリ内の説明ページの後にだけ出す。拒否時の代替と再案内を用意する。

## 選択とマッチの流れ

悩み・希望の選択からマッチ宣言までの、引き込みの核になる流れ。順序を入れ替えない。

```text
フック
  → 選択（悩み・希望、1問）※「次へ」ボタンなし、3択（3つ目は逃げ道）
      → 押した瞬間の反応（弾み・称賛・触覚、250〜400ミリ秒、現在のページで）
      → 余韻（称賛が読める間。タップから合計900〜1,200ミリ秒が目安）
      → 遷移（次のページの内容はまだ見せない）
      → [任意：選択（2問目）も同じ形]
  → マッチ宣言【結果のページ】（内容は順番に入場：映し返し → 宣言。選んだ言葉を映して「あなたにぴったり」）
  → 価値（選んだ悩みに対応する価値から並べ替える）
  → ステップ …
```

- 質問と結果は必ず別ページにする。質問のページに結果を、結果のページに質問を、それぞれ同居させない。

- 選択が1問の場合は、その答えをそのまま宣言に映す。
- 選択が2問の場合は、悩みと希望のように役割の違う2問にし、宣言では2つを1文に組み合わせる（例：［悩み］で困っているあなたが、［希望］になれるように）。
- 逃げ道（まだわからない）が選ばれた場合は、宣言を断定にしない。「まずは様子を見ながら、一緒に見つけましょう」のような誘いの言い方にし、価値の並びは標準順のままにする。
- 宣言と無関係な価値だけがアプリの強みの場合は、この流れ自体が成立していない。選択肢の作り直しに戻る。

## 反応の段階表（アニメーション・称賛・触覚）

意味のある押下への返し。強さに差を付ける。必須範囲は本編「押したら、褒める」の定義に従う（アニメーションと触覚は全段階で必須、称賛の文は中と大で必須）。

| 場面 | アニメーション | 称賛 | 触覚 |
| --- | --- | --- | --- |
| 通常の選択、次のページへ | 押した要素が軽く弾む（200ミリ秒程度） | 短い受け取りの一言、またはなしでアイコンの変化 | いちばん軽い段階（iOS は selection または impact の light） |
| 悩み・希望への回答、試し操作の成功 | 少し大きく弾み、選んだ要素が残る（300ミリ秒程度） | したことを具体的に褒める1文 | 成功の段階（iOS は notification の success） |
| 完了、最初の成功 | 一度だけの祝い（800ミリ秒程度まで、入力は塞がない） | 締めの称賛を1文 | 成功の段階を1回だけ |
| スキップ、戻る | 画面遷移のみ | なし | なし、または中立の軽い段階だけ |

- 同じ称賛文を続けて出さない。段階ごとに3通り以上を用意する。
- 動きを減らす設定では、弾みをフェードに置き換え、称賛文と状態変化で返す。
- 触覚はOS標準の機構を使い、端末の設定でオフなら鳴らさない。

## 全ページのアニメーション

すべてのページに何かしらのアニメーションを付ける。静止画だけのページは作らない。ただし、ノイズにならないことが条件である。

### 2層の構成

- 主役のアニメーション（意味のある動き）：目立たせたいものに付ける。主張を表す図形の入場と強調、ステップ番号の切り替わり、選択肢の反応、ボタンの脈打ちなど。ページ地図に「何を目立たせ、何を伝えるか」を書く。
- 常時のアニメーション（空気の動き）：背景の図形が小さく震える、ゆっくり浮く、呼吸するように伸縮する、グラデーションが緩やかに移るなど。ページが生きている感じを作るためだけの、ごく控えめな動き。

### ノイズにならないための上限

- 常時アニメーションは1ページに2要素まで。3つ以上が常時動くと、画面が落ち着かなくなる。
- 振れ幅は、移動は数ピクセル程度、回転は1〜2度程度、拡大縮小は数パーセント程度までに抑える。
- 周期は2〜4秒程度のゆっくりした繰り返しとし、要素同士の周期をずらす。同期した動きは一斉に目を引いてうるさくなる。
- 色の激しい変化、点滅、細かい高速振動は使わない。震える動きも、振れ幅の小さい小刻みなものに限る。
- 静止画として見ても主張が伝わることが前提である。アニメーションを止めて確認し、止めても意味が崩れないことを確かめる。

### 動きと意味の対応例

| 動き | 伝える意味 | 向く場面 |
| --- | --- | --- |
| 小さく震える | 寒さ、緊張、ワクワクの震え、待っている感じ | キャラクターや図形の感情を出すページ |
| ゆっくり浮く | 軽さ、自由さ、浮かぶものの性質 | 価値や期待のページの背景 |
| 脈打つ | 生きている感じ、注目してほしい合図 | 押させたいボタン、現在のステップ |
| 描かれていく | 手順が進む、作られていく | ステップのページ |
| 寄って重なる | 合う、見つかる、つながる | マッチ宣言のページ |
| 広がって収まる | 達成、解放、完了 | 接続と完了のページ |

- 対応は例であり、固定の正解ではない。対象アプリの主張に合わせて選び、選んだ理由をページ地図に書く。

### 停止と代替

- 動きを減らす設定が有効な場合、常時アニメーションは止め、主役のアニメーションは短いフェードへ置き換える。
- 画面外のページのアニメーションは止める。電池と描画の無駄を出さない。

## テンポの設計

- 通常ページの滞在目安は3〜5秒、インタラクションのページは5〜10秒、全体の完了時間は60〜120秒を目安とし、標準フローでは90秒前後を狙う（この節がテンポの数値の正本）。
- 短いページをリズムよく並べる。長いページと短いページを意図的に混ぜ、単調さを作らない。
- 山場（価値の強いページ、期待、試し操作の成功）の前後に、軽いページを置いて呼吸を作る。
- 同じ強さや同じ構図のページを3つ以上連続させない。
- 前のページで示した言葉や図形を、次のページで小さく再利用すると、流れが途切れない。
- アニメーションが終わるまで次の操作を受け付けない設計は禁止する。操作は常に受け付け、演出は割り込み可能にする。

## 演出のカタログ

使う演出は、主張を伝える、目線を導く、手応えを返す、達成を祝う、のいずれかに当てる。

- 入場：主役の要素が入ってくる動きで、主張の場所へ目線を導く。
- 進展：試し操作や選択で図形が変化し、状態が前に進んだことを示す。
- 強調：ステップの番号や、次に押す場所を一度だけ光らせる。常時点滅はしない。
- 達成：インタラクションの完了や最後のページで、控えめな祝いの動きを1回だけ出す。
- 遷移：ページが切り替わるときに、前ページの主役を次ページの主役へ引き継ぐ動きにする。

避ける演出は、意味なく回り続ける装飾、音の自動再生、長さが変わるローディング、次へ進むボタンだけに掛かる遅延である。

## 進捗の示し方（窓ドット）

総ページ数を直接数えさせないための進捗表示。何ページもあると見えるだけで、うっとおしく感じて離脱につながるため、ドットは常に窓の中だけを見せる。

### 基本仕様

- 同時に見えるドットは最大5つとする。総ページ数が5以下の場合は、通常のドットで全ページを示す。
- 現在のページのドットを大きく横長にし、隣のドットを中サイズ、窓の端のドットを小さく表示する。
- 「3 / 10」のような数字表記と、総ページ数の表示はしない。
- ドットは表示専用とする。タップによるページジャンプは付けない。

### 窓の計算

- 表示するドットの数を `窓 = min(5, 総ページ数)` とする。
- 窓の開始位置は `窓の開始 = clamp(現在のページ番号 - 2, 0, 総ページ数 - 窓)` で求める。ページ番号は0始まり（先頭ページを0）とする。現在のページが窓の中央に来るようにし、先頭と末尾では端へ寄せる。
- 表示するドットは、窓の開始から窓の個数分だけとする。窓の外のページは表示しない。
- 窓の左端より前にページがある場合は左端のドットをいちばん小さくし、窓の右端より後にページがある場合は右端のドットをいちばん小さくする。まだ続きがあることだけを示し、残りの数は示さない。

### 動き

- 1ページ進むごとに、光るドットは必ず1つ分動く。複数ページで同じドットが光り続ける圧縮表示はしない。
- 窓がスライドする場面では、ドット全体が横へ流れるアニメーションでつなぐ。瞬間的に並びが入れ替わると、現在地を見失うためである。
- 戻る操作でも同じ規則で逆向きにスライドする。進むときだけ窓が動き、戻るときは動かないという片寄りを作らない。
- 最後のページでは、光るドットが窓の右端に来る。接続ページではドットを完了の形（すべて同じ色で埋まる、またはチェックへ変わる）にしてよいが、形を変える場合は最後の1回だけにする。

### 読み上げと代替表現

- 読み上げでは総数を読み上げない。「ページ 3」の代わりに、現在の章名やステップ名（例：使い方の2つめ）で現在地を伝える。
- ドット自体は装飾として読み上げ対象から外し、現在地の情報は見出し側で重ねて伝える。

## レイアウトの原則

- 画面の上部に進捗（窓ドット）、中部に視覚の主役、下部に見出しと補足、底部に操作、の順に置く。ページ間でこの順を変えない。
- 視覚の主役が画面の面積の3割以上を占める。テキストが面積の半分を超えたら、主張の分割を疑う。
- 見出しは14歳でも読める平易な言葉で書き、文字数はおおむね20字以内に収める。
- 補足は最大2行、60字以内を目安にする。収まらない場合は本文を分けるか削る。
- スキップと戻るは全ページで同じ場所に置き、色や形を変えない。
