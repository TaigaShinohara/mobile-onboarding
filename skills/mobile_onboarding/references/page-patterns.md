# ページのパターン集

モバイルオンボーディングの7つのページ型と、テンポと演出の設計。1ページに役割を2つ与えず、1ページの主張は1つに絞る。

## 7つのページ型

### フック

- 役割：最初の1ページで引き込む。共感できる困りごとや、意外な一言を置く。
- 見出し：ユーザーの場面をそのまま表す一言、または「え、それできるの」と思わせる主張。
- 視覚の主役：その場面を表すイラストや図形、または本体の画面の一部分。
- 動き：入口で1回だけ強いアニメーションを使う。ループさせない。
- 操作：画面のどこをタップしても次へ進む。

### アイデンティティ

- 役割：何のためのアプリかを宣言する。1ページ1宣言。
- 見出し：コンセプトを1行で言い切る。社名やロゴの紹介で代替しない。
- 視覚の主役：アプリの姿を表す画面モックや象徴的なアイコン。
- 配置：オンボーディングの前半に置き、ステップより後へ回さない。

### 価値

- 役割：使うと何が変わるかを示す。1価値1ページ。
- 見出し：ユーザーが得られる変化を一言で書く。機能名ではなく変化を書く。
- 視覚の主役：変化の前後を比べる図、または変わった後の場面。
- 枚数：1〜3ページ。4つ以上の価値は、初回に要らないものを削る。

### ステップ

- 役割：基本的な使い方の1ステップを示す。ちょうど3ページで1セット。
- 見出し：動詞で始める。番号を大きく見せる。
- 視覚の主役：その操作を表す画面モックや手元の動きを示す図形。実際の操作画面に近い見た目にする。
- 連続性：3ページで同じ構図を保ち、変わる部分だけを動かす。ステップ間で学び直しを発生させない。
- 最終ステップのページでは、操作の結果として得られる状態を視覚で示す。

### インタラクション

- 役割：選択、回答、試し操作をさせる。1ページ1問。
- 見出し：質問そのものを1行で書く。
- 選択肢：2〜4個、大きくタップできるサイズで並べる。自由記述は求めない。
- 返し：選んだ直後に、その答えを受け取った一言やタイプ表示を返す。
- 置き場所：価値とステップの合間に散らす。連続2ページはインタラクションにしない。

### 期待

- 役割：ワクワクの山場を示す。使い続けると広がる楽しさや、到達できる場面を見せる。
- 見出し：未来の体験を一言で書く。
- 視覚の主役：いちばん映える場面や、成果物の例、続けると育つ要素。
- 位置：接続ページの直前に置く。途中の価値ページにも小さな山場を置いてよい。

### 接続

- 役割：本体の最初の行動へ渡す。
- 見出し：「はじめよう」ではなく、本体で最初にやることを書く。
- ボタン：押した先の画面と行動がわかるラベルにする。
- 引き継ぎ：オンボーディングの回答と試し操作の結果を、本体の初期状態に反映する。

### 許可と登録のページ（必要な場合）

- 役割：権限の許可、アカウント作成、通知の設定のいずれか1つだけ。
- 見出し：なぜ必要かを1行で書く。求める操作の名ではなく、必要になる場面を書く。
- 順序：価値が伝わった後に置く。価値の前に置かない。
- システムのダイアログ：アプリ内の説明ページの後にだけ出す。拒否時の代替と再案内を用意する。

## テンポの設計

- 通常ページの滞在目安は3〜5秒、インタラクションのページは5〜10秒、全体は60〜90秒で終える。
- 短いページをリズムよく並べる。長いページと短いページを意図的に混ぜ、単調さを作らない。
- 山場（価値の強いページ、期待、試し操作の成功）の前後に、軽いページを置いて呼吸を作る。
- 同じ強さや同じ構図のページを3つ以上連続させない。
- 前のページで示した言葉や図形を、次のページで小さく再利用すると、流れが途切れない。
- アニメーションが終わるまで次の操作を受け付けない設計は禁止する。操作は常に受け付け、演出は割り込み可能にする。

## 演出のカタログ

使う演出は、主張を伝える、目線を導く、手応えを返す、達成を祝う、のいずれかに当てる。

- 入場：主役の要素が入ってくる動きで、主張の場所へ目線を導く。
- 進展：試し操作や選択で図形が変化し、状態が前に進んだことを示す。
- 強調：ステップの番号や、次に押す場所を一度だけ光らせる。常時点滅はしない。
- 達成：インタラクションの完了や最後のページで、控えめな祝いの動きを1回だけ出す。
- 遷移：ページが切り替わるときに、前ページの主役を次ページの主役へ引き継ぐ動きにする。

避ける演出は、意味なく回り続ける装飾、音の自動再生、長さが変わるローディング、次へ進むボタンだけに掛かる遅延である。

## 進捗の示し方（窓ドット）

総ページ数を直接数えさせないための進捗表示。何ページもあると見えるだけで、うっとおしく感じて離脱につながるため、ドットは常に窓の中だけを見せる。

### 基本仕様

- 同時に見えるドットは最大5つとする。総ページ数が5以下の場合は、通常のドットで全ページを示す。
- 現在のページのドットを大きく横長にし、隣のドットを中サイズ、窓の端のドットを小さく表示する。
- 「3 / 10」のような数字表記と、総ページ数の表示はしない。
- ドットは表示専用とする。タップによるページジャンプは付けない。

### 窓の計算

- 表示するドットの数を `窓 = min(5, 総ページ数)` とする。
- 窓の開始位置は `窓の開始 = clamp(現在のページ番号 - 2, 0, 総ページ数 - 窓)` で求める。現在のページが窓の中央に来るようにし、先頭と末尾では端へ寄せる。
- 表示するドットは、窓の開始から窓の個数分だけとする。窓の外のページは表示しない。
- 窓の左端より前にページがある場合は左端のドットをいちばん小さくし、窓の右端より後にページがある場合は右端のドットをいちばん小さくする。まだ続きがあることだけを示し、残りの数は示さない。

### 動き

- 1ページ進むごとに、光るドットは必ず1つ分動く。複数ページで同じドットが光り続ける圧縮表示はしない。
- 窓がスライドする場面では、ドット全体が横へ流れるアニメーションでつなぐ。瞬間的に並びが入れ替わると、現在地を見失うためである。
- 戻る操作でも同じ規則で逆向きにスライドする。進むときだけ窓が動き、戻るときは動かないという片寄りを作らない。
- 最後のページでは、光るドットが窓の右端に来る。接続ページではドットを完了の形（すべて同じ色で埋まる、またはチェックへ変わる）にしてよいが、形を変える場合は最後の1回だけにする。

### 読み上げと代替表現

- 読み上げでは総数を読み上げない。「ページ 3」の代わりに、現在の章名やステップ名（例：使い方の2つめ）で現在地を伝える。
- ドット自体は装飾として読み上げ対象から外し、現在地の情報は見出し側で重ねて伝える。

## レイアウトの原則

- 画面の上部に進捗（窓ドット）、中部に視覚の主役、下部に見出しと補足、底部に操作、の順に置く。ページ間でこの順を変えない。
- 視覚の主役が画面の面積の3割以上を占める。テキストが面積の半分を超えたら、主張の分割を疑う。
- 見出しは14歳でも読める平易な言葉で書き、文字数はおおむね20字以内に収める。
- 補足は最大2行、60字以内を目安にする。収まらない場合は本文を分けるか削る。
- スキップと戻るは全ページで同じ場所に置き、色や形を変えない。
