# 市場の実例から得た汎用ノウハウ

実在の人気アプリのオンボーディング分解から得た、アプリを問わず使える知見をここに固定する。設計のたびに外部の事例集を調べ直さず、このファイルだけで完結させる。

このファイルは事例の寄せ集めではなく、設計の判断に使うための道具として編んである。使い方は次のとおり。

- 流派を決めるときに「1. 流派の選択」を開く。
- ページ地図を作るときに「2. 王道フローの骨格」で自分の並びを点検する。
- 個々のページの型に迷ったときに「3. 場面別の型」から引く。
- 課金ページが絡むときに「4. 課金まわり」を開き、採る型と採らない型の線引きに従う。

出典は、売れているアプリのオンボーディングと課金画面の分解事例（Onbo Hub の全87アプリの分解と型の統計、2026-11-17 調査）。登場するアプリ名は型の実例として挙げる。収益や転換率などの数字は出典側の推定または開発者の申告であり、裏取りされていない。数字は設計判断の根拠に使わず、型の存在と効き方の理解にだけ使う（「5. 数字の読み方」）。

## 1. 流派の選択：体験直結型と長尺クイズ型

市場のサブスクリプション型アプリでは、長尺のクイズ型ファネルが主流である。分解された87アプリの画面数の中央値は約33画面（最少12、最多63）で、質問にたくさん答えさせ、個別化されたプランや診断を返し、そのまま課金ページへつなぐ構成である。一方、このスキルの標準は10〜15ページ・90秒前後で本体の最初の成功へ直結させる体験直結型である。

- どちらが正しいかではなく、アプリの課金と価値の形で選ぶ。回答によって変わる個別化そのものが価値の中心で、サブスクリプション課金が主のアプリは長尺クイズ型と相性がいい。道具系、ローカル完結、無料中心、開くたびに使うタイプのアプリは体験直結型が合う。
- 長尺クイズ型を選ぶ場合も、このスキルの絶対のルール（1ページ1主張、質問と結果は別ページ、選択肢は3択で3つ目は逃げ道、結果の保証表現はしない）は維持する。緩めるのはページ数と総時間の目安だけであり、その場合は理由をページ地図に記録する。
- 長くする場合は「3. 場面別の型」の章立てを使い、長いことを感じさせない構造にする。長さ自体を目的にしない。個別化に使わない質問を水増しのために置くことは、出典側でも批判されている型であり、採らない。
- 迷ったら体験直結型を既定にする。

## 2. 王道フローの骨格

市場の87アプリで、画面の種類ごとの採用率と平均の出現位置は次のとおりだった。これは市場の標準形であり、自分のページ地図の並びを点検するための物差しとして使う。丸ごと真似るためではなく、市場の型から外れる箇所が意図的かどうかを確認するために引く。

| 画面の種類 | 採用率 | 平均の出現位置 |
|---|---|---|
| 歓迎 | 94% | 1画面目 |
| 質問（クイズ） | 98% | 3画面目から |
| 価値の提示・社会的証明 | 77%・57% | 10画面目あたり |
| 登録 | 54% | 14画面目あたり |
| 機能の案内 | 63% | 16画面目あたり |
| 権限の事前説明 | 72% | 17画面目あたり |
| 個別化された結果 | 70% | 20画面目あたり |
| 評価の依頼 | 40% | 23画面目あたり |
| 解析中の演出 | 83% | 24画面目あたり |
| 誓約・課金ページ | 21%・99% | 28画面目あたり |

読み取れる要点は3つある。

- 権限の事前説明（72%）は、このスキルの「システムのダイアログの前に理由を1行」と同じ型であり、市場の標準でもある。
- 結果を見せた後にもう一度「解析中」を挟んでから課金へ進む流れが多く、解析中の演出は結果の前だけでなく後にも置かれる。
- 誓約の画面と課金ページはほぼ同じ位置にあり、誓約は課金の直前に置く装置として使われている。

## 3. 場面別の型

### 質問の回し方

- 自己診断型の質問にする。症状や困りごとを自分で選ばせる質問は、結論（自分にはこれが必要だ）をユーザー自身に言わせる形になり、後のマッチ宣言や課金の場面で効く（QUITTR の症状チェック）。このスキルの「悩み・希望を選ばせて、ぴったりで返す」と同じ核であり、質問はアプリの強みではなくユーザーの現実から作る。
- 軽い Yes/No の連続を混ぜる。二択は考えずに押せるため、テンポが落ちない。重い質問の合間に呼吸として挟む（Calo、Symmetry の肯定文の連続）。ただしこのスキルでは選択肢は3択（3つ目は逃げ道）が原則であり、Yes/No を使う場合も「わからない」の逃げ道を欠かさない。
- 問題の再喚起を挟む。長いフローでは、5〜10画面ごとに困りごとや変化後の姿を思い出させるページを挟み、動機が切れる前に立て直す（Reframe、Wayk）。このスキルの「ワクワクの山場を途中に散らす」と同じ配置の考え方で、価値のページを質問の合間に分配する形に読み替えてよい。
- 質問の総数を先に予告する、途中で小さい達成を祝うなど、残量と進み具合が見える工夫は離脱を防ぐ（Runify の「まず6つ聞かせて」、HeyRua の初めて話せた瞬間の祝福）。このスキルの窓ドット（総数を数えさせない）と矛盾する場合は、数ではなく章や段階で進み具合を示す。
- 自由記述は原則として使わない。タップだけで進む形が離脱を防ぐという実践知が強い（Sway AI の開発者の明言）。例外として、自己啓発やスピリチュアルなど「書くこと自体が没入になる」領域では自由記述が没入と引き換えに機能するという観察もある（Stella、Aya）。このスキルでは既定をタップ式とし、自由記述を採る場合は領域の理由をページ地図に記録する。

### 待ち時間の使い方

- 解析中の演出を置く（採用率83%）。回答から結果を作っている間を「解析しています」の演出でつなぐと、結果が計算された個別のものに感じられる。演出は状態を伝える動きとして、このスキルのアニメーションの意味（つながりと状態）に当たる。
- 待ち時間に軽い質問を出す。個別化の生成や読み込みの間に、Yes/No で答えられる軽い質問を挟む型がある（Keiki が個人化の読み込み中に出している）。待ち時間を「考えてもらう時間」に変え、離脱を防ぐ。待ち時間の質問も通常の質問と同じルールを守り、答えが後の文言や初期設定に使われるものだけを聞き、結果は結果のページで返す。自由記述や重い判断を待ち時間に求めない。

### 結果の見せ方

- ビフォー／アフターを図で示す。価値のページで「使う前」と「使った後」をグラフや対比図で見せると、変化の大きさが一目で伝わる（Keiki の動画視聴と学習の比較、Cal AI の長期結果グラフ）。図の数値には根拠を持たせ、実績や研究に基づかない数字は盛らない。根拠を示せない場合は、数値ではなく場面の対比（困っている様子／解決した様子）で示す。対比は1ページに1つだけにする。
- 対峙させる数字を出す。自分の回答を生涯規模の数字に換算して突きつける型がある（Mio の「生涯で116,800時間のドゥームスクロール」、Brainrot の残りの人生のドット表示）。フックの数字（後述）と同じ系で、問題の大きさを体感させる。ただし不安を煽ることが目的化しやすく、健康や依存など機微な領域では特に慎重に扱う。数字の根拠（換算の前提）を同じページか直後に示せる場合だけ使う。
- 個別化された結果を「自分の資産」にする。回答から作ったプラン、スコア、予測を結果のページで渡すと、それがユーザーの持ち物になり、後のページや課金への接続が自然になる（AbMaxx のスコアとプラン、BigBean のレーダーチャートと道筋）。このスキルのマッチ宣言と結果のページの考え方と一致する。結果そのものをぼかして課金まで見せない形は採らない（「4. 課金まわり」）。

### 案内役と吹き出し

- マスコットや相棒のような案内役が吹き出しで質問する形式は、質問が尋問ではなく会話に感じられ、負担が下がる（Keiki、BigBean、Liftoff）。案内役の語調は称賛の語調と同じくアプリ全体でそろえ、落ち着いた道具のアプリでは静かな口調にする。案内役は演出であり主張の代わりにはならない。吹き出しの中身も1つだけにする。

### 核の動作を実際にやらせる

- 腕立てアプリがオンボーディングの途中で実際に腕立てを1回させるように、核となる動作そのものをフローの中で体験させる型がある（Pushscroll、Push Up Arena。Ziggy の最初のレッスン、Jungle のアップロードから実際の生成まで、も同系）。このスキルの「試し操作」の市場での実証例であり、説明より先に成功体験を作る。やらせるのは核の1動作だけに絞り、失敗しても進める形と「あとで試す」の逃げ道は試し操作のルールどおりに守る。

### コミットメントを形にする

- 署名と宣言。目標達成系のアプリでは、自分の名前を書く、宣言に署名するなど、意志を形に残すページを置く型がある（Wayk、Erly）。自分で書いたという事実が後の継続の動機になる。置き場所は課金ページの直前が市場の標準（「2. 王道フローの骨格」）。
- 長押しも同じ系の型である。親指を押し続ける、長押しで宣言を確定するなど、身体の動作で同意を形にする（Symmetry、Unchaind、Tolan の長押しで相棒が現れる演出）。署名より実装が軽く、触覚とも相性がいい。このスキルの「押したら、褒める」の大の反応と組み合わせる場合は、祝いではなく静かな確定の反応にする。
- 誰のために、を名指しにする。目標を抽象的な願望ではなく、特定の人や物の名前で固定すると、動機の解像度が上がる（Ziggy の「誰と手話で話したいか、その名前」）。悩み・希望の選択肢やマッチ宣言の映し返しに、名前をそのまま返す形で取り込める。
- 署名、宣言、長押しはいずれも任意とし、スキップできる形にする。強制すると離脱と反感を招く。書かせた内容は端末内保存を原則とし、扱いは悩み・希望の選択内容の保存ルールに従う。

### 長尺フローの章立て

- 40〜60画面級のフローでは、章の区切りや道筋の表示で全体を3〜4つの短い段階に感じさせる（Tipple の3章、MacroFactor の章ごとの道筋、Juno の3章の進捗バー）。長尺クイズ型を選んだ場合の必須の補助線として使う。このスキルの窓ドットと併用する場合は、ドットは章の中の位置を示し、章名が全体の進み具合を伝える形に分担させる。

### 社会的証明と評価の依頼

- 社会的証明は、冒頭と課金ページの2か所に置くのが市場の型である（利用者数、評価、研究機関やメディアのロゴ、レビューの引用）。迷いが生まれる場所がこの2か所であるため。証明の中身は検証可能な事実だけを使い、出典を示せない数字は出さない。
- 評価の依頼はオンボーディングの中に置かれることがある（採用率40%、平均は結果を見た後の位置）。置く場合は、個別化された結果を見た直後など、気持ちが前向きな位置に1回だけ置く。評価したことにするボタンや、進むために評価を求める形は採らない（「4. 課金まわり」）。

### 登録と権限の置き場

- 登録（サインアップ）の位置は調整つまみとして扱う。市場の出現位置はフローの中盤だが、最初に置く例（Bible Chat）、支払いの後に置いて摩擦を減らす例（Befit）、最後に置いて誓約の一部にする例（SNAPOUT）がある。このスキルでは既定を「価値が伝わった後」とし、動かす場合は理由を記録する。
- 機微な領域ではプライバシーの説明を質問より先に置く。健康や生活の事情を聞くアプリでは、データをどう扱うかの画面を先に出すことで、答えの正直さが上がる（MeAgain）。このスキルの、悩み・希望の選択内容の保存ルール（端末内保存が原則、目的の提示）と組み合わせて使う。

### 最初に具体的な数字を出すフック

- フックのページで、大きな具体的な数字を最初に見せる型がある（Payout の、受け取れる可能性のある金額）。抽象的な魅力より数字が引き込みを作る。数字は根拠のあるものだけを使い、受け取れる、痩せる、稼げるといった結果の保証になる数字は出さない（保証表現の禁止は従来どおり）。数字を出す場合も、そのページの主張は1つに保つ。

## 4. 課金まわり：採る型と採らない型

課金ページが入る場合の市場の型を、採るものと採らないものに分けて持つ。市場で広く行われていることは、採る理由にはならない。

### 採る型

- 課金が始まるタイミングと金額を、真剣なページとして明瞭に示す。トライアルの流れを「今日は無料、何日目に通知、何日目から課金」と日付で示すページ（Verbi、CleanEats、Lively）は、誤解なく判断できるため採用してよい。通知を約束することも含め、約束した通知は実際に出す。
- 課金ページの上でトライアルへ切り替えるスイッチを置く（RealCall、Bible Chat）。迷っている人が離脱ではなくトライアルを選べる形であり、既定でオンにしておく誘導とは分ける。
- 断られたときの引き止めは、値引きではなくトライアルの延長で返す（MenuFit の7日から14日への延長、Wayk の離脱時の2週間トライアル）。価格の信認を壊さずに済む。
- 下位のプランへの格下げ提示は認める。主力プランを割り引くのではなく、実際に安い下位プランを提示する形は、価格の線引きが正直なままである（Tolan の Plus から Lite へ）。
- 既定で選ばれているプランは、事業者に有利なものではなく、そのアプリの用途の自然な期間に合うものにする。衝動や好奇心が動機なら週単位、数週間の課題なら月単位、習慣化が目的のものは年単位が市場の対応である（Glam Up と Sprout の実践知）。安すぎる価格は価値が低いサインに見えるという観察もあるため、価格は安さでなく用途と価値で決める。
- 課金を遅らせる形も選択肢に持つ。最初は無料で使わせ、価値が分かった時点で課金ページを出す形（Sway AI の相談時の課金、StudyFetch の2文書まで無料のような使用量の上限）は、体験直結型と相性がいい。無料の範囲と課金の発生点は先に明示する。
- ハードペイウォール（無料枠を置かない形）自体は、成長の初期に収益を優先する判断としてあり得る。ただし採る場合も、閉じる導線と「買わないで進む先がない」ことの明示は欠かさない。

### 採らない型

- 閉じるボタンのない課金ページ（Cal AI）。離脱の操作自体を奪う形は採らない。
- 結果をぼかして課金まで見せない形（AbMaxx、Buck）。ユーザーの回答や素材から作った結果を人質にする形は採らない。
- 残り枠や在庫の演出（QUITTR の「残り9枠」）。実在しない希少性は出さない。
- ルーレットやスピンで当てる演出付きの割引（Cal AI、Enroad）。偶然に見せかけた予定どおりの提示は採らない。
- 段階値引きのラダー。課金ページを閉じるたびに割引率が上がる形（QUITTR の60%から92%、AbMaxx の90%）は、最初の価格が本当の価格でなかったことを示すため採らない。閉じる操作への割引提示そのものも、従来どおり採らない。
- アプリを削除しようとしたときの迎撃的な割引提示（prayer lock）。アプリの外の行動への介入は採らない。
- 評価したことにするボタン（Glam Up の「評価しました」）。押すと虚偽の申告になるボタンは置かない。出典側も倫理的に疑問と明記している型である。
- カウントダウンで急かすこと、不利なプランの初期選択で誘導すること、割引率のバッジで実質価格を読みにくくすることは、従来どおり採らない。

## 5. 数字の読み方

- 出典に載る収益、転換率、完了率などの数字は、出典側の推定か開発者本人の申告であり、第三者の裏取りはない。QUITTR の画面数のように、出典の内部でも数え方が食い違う例がある。
- したがって数字は「その型が市場に存在し、誰かが効果を主張している」ことの証拠としてだけ使う。自アプリの目標値や、利用者への約束の根拠にはしない。
- 効果の判定は、このスキルの検証（人間に通してもらい、直後に3つ聞く）と自アプリの計測で行う。市場の数字は仮説の置き場であり、答えではない。
