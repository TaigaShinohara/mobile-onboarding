# 回帰評価

架空の入力で、このスキルの判断が崩れていないかを確認する手順です。実在のアプリや利用者のデータは使いません。

## 入力（架空）

架空のアプリ「PhotoShelf」を想定します。スマホ内の写真やファイルを、本棚のようにタグで整理して後からすぐ探せるローカル完結のアプリです。初回の成功は、写真を1つ選んでタグをつけ、本棚に並ぶところまでです。

依頼は「PhotoShelf のオンボーディングを作って。まずは設計案まで」とします。

## 判定条件

次のすべてを満たす場合のみ合格とします。

- コンセプトを読み取りの根拠とともに短く記録し、読み取れていない部分を未確認として分けている。
- ページ地図の全ページで、主張がちょうど1つである。2つ以上の主張を持つページがない。
- 基本的な使い方がちょうど3ステップになっている（例：選ぶ、タグをつける、本棚に並ぶ）。
- 全ページに視覚の主役があり、テキストだけのページがない。
- インタラクションが途中に2回以上あり、各回答が後の文言か初期設定を変える設計になっている。
- 権限や登録のページがある場合、それが価値のページより後に置かれている。
- 最後のページが、本体の最初の小さな成功（写真1つにタグをつける）へ直結している。
- 進捗が窓ドット（最大5つ表示）で示され、総ページ数が数えられず、1ページごとにドットが1つ動いている。
- 悩み・希望の選択（例：探すのに時間がかかる、など場面の選択肢）が1問あり、その言葉を映したマッチ宣言が続き、宣言後の価値の並びが選択に合わせて変わっている。
- 意味のある押下に、アニメーションと称賛と触覚の3点セットが段階（小・中・大）付きで付き、スキップには称賛も成功の触覚も付いていない。
- 人間の体験確認が未実施であることを、成功に含めず未確認として残している。

## 不合格の例

- 1ページに「タグで整理できて、検索も速い」と2つの主張を載せた場合。
- 使い方が4ステップ以上に分かれ、統合の検討がない場合。
- 質問を置いたが、答えがどこにも反映されない場合。
- 最初のページで通知の許可を求めた場合。
- 10ページ分のドットをすべて表示し、総ページ数が数えられる場合。
- 悩みを選ばせたのにマッチ宣言がなく、後の並びも変わらない場合。
- 選択を押してもアニメーションも称賛も触覚も返らない場合、またはスキップにまで成功の触覚が付く場合。
